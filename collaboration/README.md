# GitHub 협업 인수인계

백가온과 박민수가 push별 변경사항·의견·읽음 확인을 주고받는 곳이다. **아직 확인이 끝나지 않은 인수인계만 `pending/`에 남긴다.** 확정된 결정과 원고·분석 결과의 기준 위치는 기존 담당 문서를 유지한다.

## 구성

```text
collaboration/
├─ README.md
├─ templates/
│  ├─ changes.md                  # push 변경사항 양식
│  └─ comment.md                  # 팀원 코멘트·읽음 확인 양식
└─ pending/
   ├─ README.md                   # 영구 안내; 삭제하지 않음
   └─ <인수인계 ID>/
      ├─ changes.md              # 이번 push에서 달라진 것·다음 작업
      ├─ 백가온.md                # 백가온의 코멘트·읽음 확인
      └─ 박민수.md                # 박민수의 코멘트·읽음 확인
```

| 팀원 | 본인이 작성할 파일 |
| --- | --- |
| 백가온 | 각 인수인계 폴더의 `백가온.md` |
| 박민수 | 각 인수인계 폴더의 `박민수.md` |

이름으로 구분하며 GitHub 아이디는 필요하지 않다. 누가 현재 작업을 요청하는 사람인지 이름 순서·PC 사용자명으로 추정하지 않는다. 보조 도구에 읽음 기록을 맡길 때는 누구를 대신하는지 알려준다.

## 따로 전달하고 싶은 내 코멘트

작업 중 “이 내용 협업 폴더에 넣어줘”라고 지정하면 해당 이름의 파일에 `사용자 전달 코멘트`로 분리한다. 변경사항 요약과 섞지 않고 원문·전달자·분류를 남긴 뒤, 저장한 코멘트와 경로도 따로 보여준다. 보조 도구의 설명을 옮긴 경우에는 그 출처를 표시한다. 자세한 기준은 [전달 코멘트 규칙](../guides/collaboration.md#user-comments)을 따른다.

## 사용하는 순서

1. 실질적인 내용 변경을 push할 때 [변경사항 양식](templates/changes.md)과 [코멘트 양식](templates/comment.md)으로 인수인계 폴더 하나를 준비한다.
2. push한 사람은 실제 공유한 내용의 커밋과 변경 이유·검증·상대에게 부탁할 일을 기록한다. push 전 초안은 완료로 표시하지 않는다.
3. 다음 사람은 [대기 폴더](pending/README.md)에서 내용을 읽고 자기 코멘트 파일에 의견과 읽은 버전을 남긴다. 의견이 없더라도 `추가 의견 없음`이라고 직접 적는다.
4. **양쪽이 최신 내용을 읽고, 중요한 내용이 담당 문서와 Git에 남아 있는지 확인한 뒤** 해당 인수인계 폴더만 삭제한다. 영구 안내와 양식은 남긴다.

판정·수정·삭제 조건의 단일 기준은 [협업 운영 규칙](../guides/collaboration.md#git-handoff)이다. 읽음은 승인·원고 편집 재개·분석 실행 허가가 아니다. 자동 열람 감지나 자동 삭제 프로그램은 설치하지 않았다. 작업자가 기록과 조건을 확인해 정리하며, Git 커밋·push는 별도 요청 범위에서 수행한다.
