## 사용자 전달 코멘트 구분 추가 — 내용 버전 3

사용자가 작업 중 따로 전달하도록 지정한 내용은 각 팀원 파일의 `사용자 전달 코멘트`에 분리하도록 협업 규칙·공통 지침·폴더 안내·양식을 갱신했다. 원문·전달자·분류·출처를 구분하고 저장 후 코멘트와 경로를 별도로 보여준다. 보조 도구의 설명과 일반 검토 의견은 별도 절에 둔다.

버전 3 작성 시점에는 두 팀원 파일에 빈 구분 절만 추가했다. 당시 발화자의 이름을 아직 확인하지 못했으므로 어느 팀원의 실제 전달 코멘트로도 배정하지 않았다. 코멘트 버전 0과 양쪽 미확인은 그대로였으며 push·삭제도 하지 않았다. 이는 전달 방식에 관한 공통 운영 규칙 추가다.

## 요청자 확인 — 내용 버전 4

2026-09-27 이 협업 설정 작업의 사용자가 “난 백가온이야”라고 본인을 확인했다. 이후 이 작업에서 따로 저장하도록 지정한 ‘내 코멘트’는 백가온의 `사용자 전달 코멘트`로 구분한다. 이 확인을 다른 팀원의 작업이나 모든 새 작업의 사용자 신원으로 일반화하지 않는다.

이름 확인만 기록했으며 실제 전달 코멘트 추가·읽음 완료·push 담당자 확정·외부 전송으로 처리하지 않았다. 두 팀원의 코멘트 버전 0과 미확인 상태는 유지한다.

## 초기 폴더 생성 검증과 한계 — 내용 버전 2 시점

- 새로 만들거나 수정한 MD 12개의 로컬 인라인 링크 70곳을 검사했고 깨진 경로·Markdown 앵커는 없었다. 두 팀원의 코멘트 파일은 이름만 지정되어 있으며 코멘트 버전 0·미확인 상태다. 인수인계는 `DRAFT`를 유지한다.
- 작업 전 MD·HTML·Python/JavaScript·YAML·실행 manifest 414개를 해시로 기록해 비교했다. 이 중 기존 안내 문서 5개(README, AGENTS, GitHub 공유 안내, 협업 규칙, 작업 안내)만 변경됐고 나머지 409개는 동일하다. 없어진 파일은 없고 협업 폴더의 MD 7개만 추가됐다. 원본 데이터 전체 재해시는 하지 않았다.
- 별도 읽기 전용 문서 검토에서도 삭제 조건·확인 버전·초안 상태의 모순을 발견하지 못했다. 자동화 프로그램이나 실제 삭제·복원 동작을 테스트했다는 뜻은 아니다. 이 검증 기록을 반영하면서 내용 버전을 2로 올렸다.
- 아직 커밋·push·원격 확인은 하지 않았다. 읽음 감지·자동 삭제 스크립트나 Git hook은 만들지 않았다.
- 데이터 재수집·재분석·미리보기 재생성·Google Drive/Docs 반영·블로그 게시는 하지 않았다.
