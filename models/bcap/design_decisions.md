## 공통 수식·부호·분모

같은 평가 집단 `T`에 대해 `Y`는 해당 행의 최종 PA 공격가치, `A=1`은 PITCH의 FB 또는 SWING의 번트 포함 공격 시도다. `A=0`은 NFB 또는 판정상 Take다. 정책에 허용된 Z는 X의 일부이고, 개인 효과를 포함한 X를 양 행동 평균화에서 보존한다.

```text
phi1_i = mu1_i + A_i / e_i * (Y_i - mu1_i)
phi0_i = mu0_i + (1-A_i) / (1-e_i) * (Y_i - mu0_i)
Q_a(T) = sum_{i in T} phi_a_i / |T|
Delta(T) = Q_1(T) - Q_0(T)
V_d(T) = mean_{i in T} [d_i * phi1_i + (1-d_i) * phi0_i]
V_observed(T) = mean_{i in T} Y_i
Pitch gain = V_observed - V_d
Swing gain = V_d - V_observed
```

확률적 정책은 `0 <= d_i <= 1`, 결정론적 정책은 `d_i in {0,1}`이다. 부호가 반대인 두 모델의 gain을 섞지 않는다. 같은 PA의 모든 투구에 붙은 Y는 여러 개의 독립 결과가 아니므로 경기를 fold·구간 계산 단위로 묶는다. 출력에서 행 수, PA 수, 경기 수를 별도 보존한다.

보수 정책에서 `H_i=1`은 정책을 변경할 근거가 있는 사전 지정 영역이고 나머지는 실제 행동 메커니즘을 유지한다고 정의하면:

```text
V_conservative(T) = mean_{i in T} [
    H_i * {d_i*phi1_i + (1-d_i)*phi0_i} + (1-H_i)*Y_i
]
```

`H_i`를 해당 평가 행의 Y 또는 평가된 효과를 보고 골라서는 안 된다. 정책은 학습 자료에서 정하고 평가집단 공통 지지 마스크와 역할을 구분한다. 현재 식은 한 구 평가용이며 PA의 모든 행에 동시에 적용한 정책의 가치가 아니다.

## 검수자가 실제 실행에서 확인할 연결

1. 선택된 각 입력의 시간 계보와 금지 변수 검사, 닫힌 구종·행동 매핑 및 실제 개발 문자열 감사가 일치하는지 확인한다.
2. outer 평가 경기가 inner 튜닝·전처리·calibration·정책 학습에서 빠졌는지, 모든 반복 PA와 경기 내 투구가 같은 fold에 있는지 확인한다.
3. 최종 개발 정책의 파일 해시가 외부 열람 전 봉인에 포함됐는지 확인한다. 외부 evaluation nuisance의 refit을 정책 재학습으로 섞지 않는다.
4. 2026 PITCH 코드에 lag 위치·zone 파생 입력이 들어가지 않았는지, SWING 외부 수치가 임의 대리 분석으로 채워지지 않았는지 확인한다.
5. 구간의 범위, 다중비교 가족, 전체 재학습의 실제 횟수·실행 여부, 등급 상한 및 이유 코드가 실행 결과·보고서에 그대로 반영됐는지 확인한다.

이 기록 작성 시 검토자는 2023·2026 BCAP 행동별 결과를 보지 않았다. 실행 후 발견한 코드와 문서 차이는 실제 구현에 맞춰 정정 이력으로 남겨야 하며, 외부 열람 뒤 결과에 영향을 주는 설계 변경은 새 버전·새 실행 ID를 사용한다.
