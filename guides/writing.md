# 집필 원칙

## 모델 해설의 구성 — 2026-09-28 사용자 지정

- BCAI·BCAP 해설은 본문을 읽어 결과를 이미 아는 독자가 계산 방법을 더 살펴보는 글로 쓴다. 질문→답변 구성을 사용하지 않는다.
- 초반에는 본문의 결과표를 재사용해 계산 대상만 상기시킨다. 이후에는 분석 결과·시즌별 패턴을 반복하지 않고 입력 정리부터 최종 값·표시 산출까지 계산 순서대로 설명한다.
- BCAI는 타석 정리·결과 가중치·카운트 도달 집계·평균·100 기준 환산·연도 요약·불확실성을 이어 설명한다. BCAP는 공통 계산을 먼저 풀고 위치·스윙·구종의 세 비교를 나누어 설명한다. 구종 안에서는 FB/NFB와 FF/비포심을 구별한다.
- 계산 예시는 가상 여부를 명시하고, 단위·분모·보정·지원 조건 등 계산을 이해하는 데 필요한 해석 메모는 유지한다. 아래 본문의 질문형 전개 및 과거 해설의 결과 우선 지침보다 이 모델 해설 전용 지침을 우선한다.

## 주제별 설명 순서 — 2026-09-27 추가 피드백

- 질문을 던지며 설명하는 흐름을 살린다. 장과 세부 절에서 독자의 자연스러운 질문을 제시하고, 바로 짧은 답·핵심 결과를 준 다음 예시와 근거로 풀어간다. 질문형 제목만 붙이거나 결론을 뒤로 미루지 않는다. 세 단계 목차와 분리된 결과 영역은 유지한다.

- 본문의 분석 주제마다 `간단 설명(한두 문장) → 결과 한눈에 보기 → 상세 설명`을 반복한다. 글 맨 앞에 서로 다른 모델의 결과를 한꺼번에 모아 독자에게 먼저 외우게 하지 않는다.
- 각 장에서 앞으로 설명할 항목과 순서를 짧게 안내한다. 큰 제목은 주제, 작은 제목은 세 단계, 그 아래 제목은 세부 풀이로 구별한다.
- 결과 표는 해당 독자의 질문에 맞춰 새로 구성한다. 기존 표의 단순 복사 대신 결과·단위·읽는 뜻을 연결하되 수치는 검증된 기존 결과를 사용한다.

## 본문과 해설의 역할 — 2026-09-27 승인

- 본문은 일반 야구팬이 주요 결과와 경기의 의미를 이해하는 글로 쓴다. 결과 우선 구성과 이해를 돕는 예시는 유지한다.
- 계산의 정의는 모델 해설, 외부 연구의 상세 내용은 문헌 해설, 자체 데이터·검증·개발 과정은 검증 글에서 맡는다. 필수 단위·분모·적용 범위는 결과 옆에 짧게 남긴다.
- 일반 용어는 처음 등장할 때 쉬운 말로 풀고 필요한 짧은 용어주를 붙인다. 용어 번호와 문헌 번호를 구분한다.
- 본문을 축약할 때는 이동 대조표로 근거·시행착오의 보존을 확인한다. 문헌 해설의 상세 설명을 본문과 함께 일괄 축약하지 않는다.
- 로컬 검토 링크와 공개 게시 주소를 구별한다. 공유 묶음은 그림·연결 파일을 포함해 이동 후 확인한다.


## 원고 관리
- 칼럼별 `column.md`를 중심 문서로 사용한다. 기획 메모와 본문을 구분한다.
- Google Docs 공동 집필을 시작하면 해당 Docs를 본문의 최신본으로 지정하고 `column.md`에 링크한다. `column.md`는 질문·가설·분석 결과·상태를 관리하며, 로컬 원고 사본에는 기준일을 표시한다. 세부 운영은 `collaboration.md`를 따른다.
- 기본 독자층은 야구를 좋아하지만 세이버 지표와 통계에는 익숙하지 않을 수 있는 팬으로 둔다. 칼럼별 요청이 있으면 조정한다.
- 모든 설명은 두괄식으로 쓴다. 글 전체와 각 절·소주제의 결과 또는 핵심 뜻을 먼저 제시한 뒤, 근거·계산 방법·이유·해석 범위를 설명한다. 결과를 뒤로 미루며 궁금증을 유도하는 순서보다 이 원칙을 우선한다. MLB 발견과 KBO 검증은 실제 완료 범위를 구분한다.
- 확인된 사실, 분석 결과, 작성자의 해석을 구분한다.
- 지표는 처음 등장할 때 뜻과 해석 방법을 설명한다. 계산법은 정확성을 유지하면서 읽기 쉽게 풀어 쓴다.
- 원고의 실제 수치에는 추적 가능한 출처 또는 해당 분석 결과를 연결한다. 참고 문헌은 칼럼별 `sources.md`에 정리한다.

## 시각자료와 발행
- 표와 차트에 제목, 단위, 기간, 표본 수, 출처를 표시한다.
- 인스타그램 자료는 칼럼 결과가 정리된 뒤 핵심 내용을 카드별로 구성한다. 요약 과정에서 불확실성과 결론의 범위를 왜곡하지 않는다.
- `figures/`는 표·차트, `publish/`는 검토된 발행용 원고와 인스타그램 문구·이미지에 사용한다.
- 실제 발행 전에는 상태를 “발행”으로 표시하지 않는다.

## 결과·설명·문헌의 위계 — 2026-09-18 사용자 피드백

- 모델 해설은 결과 전체를 앞쪽에 모으고 요약표·세부 결과표·그림을 별도 결과 영역에 둔다. 계산 중간에 결과가 묻히지 않게 한다.
- 설명은 BCAP 해설처럼 용어를 풀고 예시를 이어 붙인다. 설명의 순서는 결과·핵심 → 자세한 풀이로 유지한다.
- 본문에서 BCAI·BCAP를 처음 쓰기 전에 역할을 짧게 소개하고, 각 사용 지점에서도 사용한 도구와 비교 대상을 한두 문장으로 표시한다.
- 큰 제목·작은 제목·단계 번호로 내용의 상하 관계를 표시한다. 결과 요약, 해석 메모, 참고문헌은 제목과 별도 서식을 함께 사용해 구별한다.
- 해석 메모를 적극적으로 사용한다. 결과의 단위·분모·불명확·자료 부족·적용 범위는 본문과 구별하되 읽기 어렵게 숨기지 않는다.
- 참고문헌은 자체 결과와 다른 전용 양식으로 소개한다. 외부 연구의 핵심과 현재 글의 사용 범위, 원문·한국어 해설 연결을 함께 둔다.
