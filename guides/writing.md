# 집필 원칙

## 원고 관리
- 칼럼별 `column.md`를 중심 문서로 사용한다. 기획 메모와 본문을 구분한다.
- Google Docs 공동 집필을 시작하면 해당 Docs를 본문의 최신본으로 지정하고 `column.md`에 링크한다. `column.md`는 질문·가설·분석 결과·상태를 관리하며, 로컬 원고 사본에는 기준일을 표시한다. 세부 운영은 `collaboration.md`를 따른다.
- 기본 독자층은 야구를 좋아하지만 세이버 지표와 통계에는 익숙하지 않을 수 있는 팬으로 둔다. 칼럼별 요청이 있으면 조정한다.
- 모든 설명은 두괄식으로 쓴다. 글 전체와 각 절·소주제의 결과 또는 핵심 뜻을 먼저 제시한 뒤, 근거·계산 방법·이유·해석 범위를 설명한다. 결과를 뒤로 미루며 궁금증을 유도하는 순서보다 이 원칙을 우선한다. MLB 발견과 KBO 검증은 실제 완료 범위를 구분한다.
- 확인된 사실, 분석 결과, 작성자의 해석을 구분한다.
- 지표는 처음 등장할 때 뜻과 해석 방법을 설명한다. 계산법은 정확성을 유지하면서 읽기 쉽게 풀어 쓴다.
- 원고의 실제 수치에는 추적 가능한 출처 또는 해당 분석 결과를 연결한다. 참고 문헌은 칼럼별 `sources.md`에 정리한다.

## 시각자료와 발행
- 표와 차트에 제목, 단위, 기간, 표본 수, 출처를 표시한다.
- 인스타그램 자료는 칼럼 결과가 정리된 뒤 핵심 내용을 카드별로 구성한다. 요약 과정에서 불확실성과 결론의 범위를 왜곡하지 않는다.
- `figures/`는 표·차트, `publish/`는 검토된 발행용 원고와 인스타그램 문구·이미지에 사용한다.
- 실제 발행 전에는 상태를 “발행”으로 표시하지 않는다.

## 결과·설명·문헌의 위계 — 2026-09-18 사용자 피드백

- 모델 해설은 결과 전체를 앞쪽에 모으고 요약표·세부 결과표·그림을 별도 결과 영역에 둔다. 계산 중간에 결과가 묻히지 않게 한다.
- 설명은 BCAP 해설처럼 용어를 풀고 예시를 이어 붙인다. 설명의 순서는 결과·핵심 → 자세한 풀이로 유지한다.
- 본문에서 BCAI·BCAP를 처음 쓰기 전에 역할을 짧게 소개하고, 각 사용 지점에서도 사용한 도구와 비교 대상을 한두 문장으로 표시한다.
- 큰 제목·작은 제목·단계 번호로 내용의 상하 관계를 표시한다. 결과 요약, 해석 메모, 참고문헌은 제목과 별도 서식을 함께 사용해 구별한다.
- 해석 메모를 적극적으로 사용한다. 결과의 단위·분모·불명확·자료 부족·적용 범위는 본문과 구별하되 읽기 어렵게 숨기지 않는다.
- 참고문헌은 자체 결과와 다른 전용 양식으로 소개한다. 외부 연구의 핵심과 현재 글의 사용 범위, 원문·한국어 해설 연결을 함께 둔다.
