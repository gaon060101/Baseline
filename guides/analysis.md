# 분석 원칙

## 핵심 방향: MLB에서 가설을 만들고 KBO에서 검증

1. 칼럼의 질문을 먼저 정하고 필요한 MLB 데이터와 기간을 선택한다.
2. MLB 데이터를 탐색해 패턴을 찾고, KBO에도 적용되는지 확인할 가설을 만든다.
3. KBO 결과를 보기 전에 가설, 예상 방향, 대상 기간·선수, 비교 집단, 주요 지표, 제외 기준과 판단 기준을 해당 `column.md`에 기록한다.
4. 필요한 KBO 데이터를 확보하고 같은 개념을 측정하도록 필드·단위·분모를 맞춘다.
5. KBO 결과가 가설을 지지하는지, 지지하지 않는지, 자료가 부족해 판단할 수 없는지 보고한다.

사용자가 말한 “증명”은 결과를 미리 정하는 것이 아니라 데이터로 검증한다는 뜻으로 적용한다. 가설이 맞지 않는 결과도 칼럼의 유효한 결론이다. 관찰 데이터만으로 인과관계나 보편적인 법칙을 입증했다고 단정하지 않는다.

## 비교와 해석
- MLB와 KBO의 시즌, 규칙, 득점 환경, 선수 구성, 구종 분류, 측정 방식 차이를 확인한다.
- 가설에 따라 좌우 유형, 선수 수준, 구장, 점수 차, 주자·아웃 등 필요한 비교 조건을 정한다.
- 탐색 후 바뀐 가설은 변경 이유와 함께 기록한다. KBO 결과를 본 뒤 만든 설명은 사전 가설 검증과 구분한다.
- 투구 수, 타석 수, 경기 수, 선수 수를 구분한다. 많은 투구가 소수 선수에게 집중되어 있는지도 확인한다.
- 주요 결과에 분모, 표본 수, 분석 기간과 적절한 불확실성 설명을 붙인다. 표본 크기만으로 결론이 충분하다고 판단하지 않는다.

## 데이터 관리
- 원본: 칼럼별 `data/raw/mlb/`, `data/raw/kbo/`. 원본은 보존한다.
- 정제본: `data/processed/`. 원본에서 재생성할 수 있게 처리 과정을 남긴다.
- 확보한 파일의 출처·기간·확보일·방식·이용 조건·결측과 한계는 `sources.md`에 기록한다.
- 구속 단위와 카운트의 투구 전후 기준을 명시한다. 볼카운트별 구종 선택은 투구 전 카운트로 분석한다.
- 결측은 0으로 바꾸지 않는다. 타석 식별자와 투구 순서를 보존하고, 중복·누락·타석 종료 결과를 검증한다.
- 칼럼별 계산과 검증 기록은 `analysis/`, 완성된 표·차트는 `figures/`에 둔다.
- 코드 공통화는 실제로 재사용할 필요가 생겼을 때 `shared/`에서 진행한다.

## 분석 모델 관리

- 모델명에는 리그·시즌을 넣지 않는다. 모델 ID는 `BCAI-OBS-v1.0.0`처럼 설계와 버전을 식별한다. 모델 정의의 기준 위치는 `models/<family>/<variant>/<version>/`, 전체 목록은 [레지스트리](../models/registry.md)다.
- 실행 ID 기본형: `<model>__<league>_<period>__<YYYYMMDD>__r<번호>`. model은 소문자 실행 별칭(예: bcai_obs), 번호는 최소 두 자리이며 같은 별칭·리그·기간·날짜에서 미사용 번호를 고른다. 버전이 달라도 기존 ID를 재사용하지 않는다. 정확한 버전은 manifest.model_id/version에 기록한다.
- 실행일은 실제 계산일이며 사후 등록일과 구분한다. 현재 r01 두 건은 2026-09-07 공동 실행을 2026-09-08 등록한 기록이다.
- 상태는 `DRAFT`(설계 중), `EXPERIMENTAL`(탐색), `VALIDATED`(명시 범위 검증), `DEPRECATED`(사용 비권장), `SUPERSEDED`(후속 대체) 중 하나. VALIDATED도 인과성·미래 예측·다른 리그 일반화를 보증하지 않는다. 변경 근거·날짜·대체 버전을 기록한다.
- 버전: Major=추정 대상·핵심 공식 변경; Minor=변수·보정·등급 등 결과에 영향을 주는 설계 변경; Patch=수치에 영향 없는 문서·표기 수정. 새 리그·시즌 적용 자체는 새 실행이며 설계 변경이 있을 때만 버전을 바꾼다. 최초 등록은 사용자 지정 버전을 유지한다.
- 모델 카드·specification.yaml은 설계 기준, validation.md는 검증 범위/근거, 실행 manifest는 실제 가중치·기준값·표본·입력/출력 경로와 해시·코드·환경·실행일·이전/후속 실행을 담당한다. 실행별 수치를 모델명에 넣지 않는다.
- 결과는 칼럼별 실행에 단일 보관한다. 기존 공동 CSV는 파일을 복제하지 않고 모델별 열/JSON 선택자를 manifest에 기록하는 예외를 허용한다. OBS의 CI·등급을 Ridge에 전용하지 않는다.
- 경로 변경 전 이동/유지 목록과 해시를 기록하고 모든 코드·문서 참조를 수정한다. 원본·기존 정제본은 이동/덮어쓰기 금지. 등록 완료 실행은 보존하고 재실행은 새 ID로 수행한다.
- 구조 변경만으로 재수집·재분석·Drive 업로드를 시작하지 않는다. [BCAI 재현 안내](../models/bcai/README.md)를 따른다.
