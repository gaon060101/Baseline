# Baseline 드라이브 협업 안내

## GitHub 협업 추가 — 2026-09-16

사용자 요청으로 코드·문서·모델 정의·집계 결과를 GitHub 공유 대상으로 분리한다. [공유 범위](github_sharing.md), [팀원 데이터 준비](data_setup.md), [제외 파일 목록](excluded_files.json)을 따른다. 원본/행별 자료/캐시/설치 라이브러리는 로컬에 유지하며 Git 업로드에서 제외한다. GitHub 업로드는 Google Drive/Docs 동기화가 아니다. 아래는 기존 Drive 운영 규칙이다.


## 저장 위치와 역할

공유 대상: https://drive.google.com/drive/folders/1kIsnL50yB1T7tkCkAqDhAcct9k_sZbVs

- 로컬 Baseline: 작업 지침, 원본 데이터, 정제 과정, 분석 코드와 검증 기록의 기준 위치.
- Google Drive: 팀원이 볼 정제 데이터, 요약표, 차트, 출처 설명, 공동 원고, 발행용 자료.
- Google Docs 공동 원고를 만든 이후에는 Docs가 본문의 최신본이다. 생성 전에는 로컬 `column.md`가 원고 기준이다.
- 업로드한 CSV는 분석 결과 스냅샷이다. 수정 의견은 별도로 기록하고 로컬 분석을 재실행해 새 버전을 공유한다.

## 드라이브 폴더 구조

```text
Baseline/
├─ 협업안내.md
├─ 프로젝트구조.md
└─ 001-first-column/
   ├─ 01-공동원고/          # Google Docs: 집필 시작 시 생성
   ├─ 02-정제데이터/        # 검증된 CSV·엑셀·요약표
   ├─ 03-차트/              # 원고에 쓰는 이미지
   ├─ 04-출처와분석설명/    # 출처·단위·분모·방법·한계
   └─ 05-발행본/            # 검토를 마친 게시용 자료
```

칼럼 번호를 로컬과 드라이브에서 동일하게 쓴다. 주제 확정 시 이름과 링크 기록을 함께 관리한다. 필요한 자료가 없을 때 예시 결과나 빈 공동 원고를 임의로 만들지 않는다.

## 업로드 절차

1. 사용자가 지정한 칼럼과 공유할 자료를 확인한다. 업로드 요청 범위 안에서 실행한다.
2. 정제 데이터의 기간·단위·표본 수·결측·분모와 차트의 출처를 검증한다.
3. 공유 가능한 정제본·설명·차트만 올린다. 원본 데이터는 공유 필요성과 이용 조건을 확인한 경우 포함한다.
4. 데이터·차트 스냅샷은 `이름_YYYY-MM-DD_v01`처럼 버전을 표시한다. 같은 이름을 발견하면 내용을 확인하고 중복 업로드를 피한다.
5. 기존 공동 원고는 팀원 수정 내용을 먼저 읽고 요청한 부분을 반영한다. 로컬 사본으로 덮어쓰지 않는다.
6. 업로드 후 파일 이름·부모 폴더·링크를 확인하고 칼럼의 `collaboration.md`에 기록한다.
7. 사용자에게 로컬 변경과 드라이브 반영 결과를 나누어 보고한다.

## 운영 안내

- 플러그인 연결은 폴더 자동 동기화가 아니다. 현재는 요청에 따른 업로드 방식이다.
- 팀원은 본인 Google 계정으로 초대한다. 팀원 초대나 공개 링크 전환은 별도 요청을 받는다.
- 2026-09-05 연결 확인 시 최상위 폴더에는 소유자 권한만 있었다. 팀원 초대 완료 여부는 실제 권한으로 확인한다.
- 구조나 협업 규칙 변경 시 로컬 README와 관련 지침을 갱신한다. 드라이브 안내 파일은 공유 사본이며, 업로드 성공 시에만 동기화 완료로 보고한다.
