# BCAP R 구현 검토 기록

검토일: 2026-09-28. **계산 구현·입력 연결의 제한된 확인이며 통계적 추론의 타당성 검증은 아니다.** BCAP R 계산부 작성자와 다른 에이전트가 Python 정의와 대조하고 별도 모의자료를 구성했다. 원자료 준비 코드 `prepare_raw.R`는 이 검토자가 작성했으므로 그 부분은 독립 구현 감사가 아니라 제작자 자체검산으로 구별한다.

## 확인한 범위

- 비교 기준: `models/bcap/development_v2/v0.2.0/engine.py`, `run.py`, `models/bcap/data.py`, V2 `prepare.py` 및 PITCH·S/B·SWING·FF의 기존 명세.
- R의 훈련 내부 범주 사전, 중심화한 ridge, 미지 범주의 기여 0, Platt 보정, 행동별 결과모형, OOF AIPW와 원 Python 계산 구조를 대조했다. 기존 규제값·경기 분할을 재생하는 실제 전체 자료 재현 결과는 각 실행의 `checks.json`이 별도 기준이다.
- 지원 표본의 N·행동별 ESS·행동별 경기 수·지원율·최대 경기 가중치 조건이 기존 Python과 일치했다.
- 단일 연도의 `game_year`는 한 범주가 되어 중심화 후 기여가 0이다. 다른 연도에도 같은 코드 구조를 적용할 수 있지만, 적합 성공·예측력·외부 일반화를 보장하지 않는다.

## 별도 모의검증 결과

[독립 검토용 모의검증 코드](../../../../models/bcap/r/test_independent_review.R)를 저장하고 **한 번 실행하여 PASS**를 확인했다. 실제 데이터 읽기·파일 생성·모형 적합 없이 다음을 점검한다.

| 항목 | 확인 결과 |
|---|---|
| 유효 표본 수 | 500행은 통과, 다른 조건을 유지한 499행은 실패 |
| 행동별 ESS | 최소 200은 통과, 199는 실패 |
| 행동별 경기 수 | 최소 100경기는 통과, 99경기는 실패 |
| 지원율 | 정확히 0.5는 통과, 나머지 조건을 유지한 0.5 미만은 실패 |
| 최대 경기 가중치 비율 | 정확히 0.05는 통과, 0.05 초과는 실패 |
| 지원 표본 없음 | 점추정을 결측으로 남기고 `비교 자료 부족` 판정 |
| 불균등한 경기별 행 수 | 직접 계산한 경기별 중심화 잔차합으로 표준오차와 t 구간 재확인 |
| 보수적 비교 상한 | 255를 사용한 구간이 232를 사용한 구간보다 좁아지지 않음 |
| 단일 연도 | 상수 연도 범주의 중심화 결과가 0 |
| SWING 측정 지원 | 정상 물리량만 통과, Inf·NA·누락 구역·미분류 구종은 실패 |

재현 명령은 저장소 루트에서 다음과 같다.

```powershell
& ./tools/run_r.ps1 -Script ./models/bcap/r/test_independent_review.R
```

출력: `PASS independent BCAP review: five gate boundaries, no-support behavior, unequal-game cluster arithmetic, conservative family, single-year block and finite measurement support`

## 원자료 준비 자체검산

별도 모의검증 [test_prepare_raw.R](../../../../models/bcap/r/test_prepare_raw.R)에서 PA 제외 순서, 마지막 행 이벤트만 사용, 제외 전 동일 PA 내 직전 투구 생성, 닫힌 구종·스윙 분류, S/B 경계, 기존 범주 문자열, 명시적 연도 가중치, 2026 기하 보류를 확인했다. 작은 모의 CSV·일정·설정을 사용한 RDS/CSV/감사 기록 왕복과 기존 출력 재작성 거부도 확인했다.

실제 자료는 2024년 `game_pk=744795` 한 경기만 따로 확인했다. 원자료 `data/raw/mlb/2024/statcast_2024-09-21_2024-09-25.csv`의 해당 **279행**을 R에서 준비하고, 기존 Python 준비본을 변환한 `analysis/runs/bcap_r_input__mlb_2024_2025__20260928__r01/rows.csv`의 **40개 공통 필드**와 대조했다.

- 행동·자격·범주 문자열·Y가 일치했다.
- 물리량 차이는 `plate_x` 최대 `4.884981e-15`, `plate_z` 최대 `5.329071e-15`; 나머지 비교 물리량은 0이었다. 수치 허용치 `1e-12` 이내다.
- 한 경기 확인 결과를 전체 연도 원자료 복원 검증으로 확대하지 않는다. 경기 ID 집합 일치 역시 경기 안의 모든 투구·PA가 완전함을 증명하지 않는다.

## 검토 중 발견한 사항과 반영 확인

1. **SWING의 Inf 물리량 지원 문제:** `!is.na`만 검사하면 Inf가 지원 표본에 포함되는 것을 한 행 모의자료로 재현했다. 계산부 작성자가 `bc_swing_measurement_support()`의 `is.finite` 검사로 수정했고, 위 독립 모의검증에서도 거부를 재확인했다. 실제 2024·2025 자료가 이 문제의 영향을 받았다고 확인한 것은 아니다.
2. **원 실행의 구역 검사 누락:** 타석 방향 확인, 구역 소속 최대 2개, CENTER와 기하 S 행동의 일치 검사를 복원하도록 전달했다. 현재 `run.R`에 세 검사가 있고, 2026 측정 보류와 구별하여 2025년 이전에 CENTER 일치를 검사하는 것을 코드 열람으로 확인했다. 이 기록에서는 전체 자료 적합을 추가 실행하지 않았다.
3. **역사 입력 연결 검증:** 현재 [역사 실행기](../../../../tools/run_bcap_history.py)는 완료된 BCAI manifest의 해시와 `config.json`·일정·가중치 출처·provenance를 대조한 뒤 원 CSV의 해시를 확인한다. 기존 RDS를 재사용할 때 감사 기록의 실제 가중치가 현재 BCAI 설정과 같은지 검사하고, 준비본과 수치 입력 해시를 확인하도록 수정된 코드를 열람했다.
4. 새 실행·설정·로그와 불완전한 기존 준비본을 덮어쓰지 않는 방어, 동시 실행 잠금, BCAI 입력 실패 시 대기 중단 조건을 코드에서 확인했다. 실제 과거 연도 전체의 성공 여부는 실행별 manifest를 따른다.

## 해석 경계

- 네 모듈의 현재 표시 집합은 `13 + 13 + 193 + 13 = 232`개다. 역사 실행의 255는 **각 연도에 미리 정한 보수적 비교 상한**이며, 실제 255개 결과가 산출된다는 뜻이 아니다. 여러 연도 전체에 대한 동시 95% 보장으로 부르지 않는다.
- 구간은 고정된 OOF 점수의 경기 군집 조건부 t 근사다. 보조 모형 전체 재학습 변동, 경기 간 선수 의존성, 실제 95% 포함률은 검증하지 않았다. 2024·2025 차이에도 공유된 학습 모형의 불확실성이 빠져 있다.
- 현재 `year_differences.csv`는 별도의 255 비교 상한을 사용한다. 일반 `comparison_family` 변경이 연도 차이 보정까지 바꾸는 인터페이스는 아니다. 역사 단일 연도 실행에는 이 차이 표가 생성되지 않는다.
- 2015·2016 구속의 측정 방식 차이는 준비 감사에 남기고, 2026 S/B·SWING 기하 보류를 유지한다. 이 검토는 인과 효과·행동 추천·정책 개선·KBO 검증이나 모델 상태 승격의 근거가 아니다.

## 이후 원자료 준비 보강과 일정 검사

2026-09-28 추가 확인. 준비 코드는 동일 경기의 일정 별칭을 `game_pk·year·venue·official_date·cutoff`가 모두 같을 때만 하나로 합치고, 중복 수와 목록을 기록한다. 다른 메타데이터가 있으면 준비를 중단한다. 2023년 초기 실패 준비본은 보존했으며, 동일 별칭 처리 후 새 준비 시도에서 실행 담당자가 720,684행·유효 183,534타석의 성공을 확인했다.

완료 경기 판정은 BCAI와 동일하게 정규시즌·abstract Final·coded F·detailed Final 또는 Completed Early를 모두 요구한다. 2020년 abstract Final인 미실시 연기 경기 631471·631472를 제외하여 900경기 대신 실제 898경기를 요구한다. [보관 일정 검사](check_preparation_schedule.R)는 2020~2026 모든 일정 기록에서 두 판정 함수가 일치함을 대조한다. 결과는 [감사 JSON](preparation_schedule_check.json)에 기록했다. 2026은 구 필터 2,192개 기록과 새 필터 2,166개 기록 모두 같은 2,165경기를 남긴다.

이 검사에서 **추가로 확인된 BCAP 준비 차단 조건**은 2020년 경기 630882의 구장 3309/2 충돌과 2021년 경기 633224의 구장 4705/2680 충돌이다. 각각 officialDate는 2020-08-09, 2021-07-21로 같다. 완료 경기 집합 판정은 통과하지만, 동일 경기의 구장을 하나로 임의 선택할 수 없으므로 해당 준비는 충돌 방어에서 멈춘다. 2022~2026에는 같은 유형의 충돌이 없다. 이 기록은 해당 연도 BCAP 적합이 완료됐다는 뜻이 아니다. 구장 특징의 처리 기준을 근거와 함께 별도로 확정해야 한다.

또한 준비 코드는 고정된 저장소 경로 대신 실제 `--file` 또는 `source()`로 읽은 파일을 시작 시 해시로 확인하고, 입력 검사·동결 사본·감사 코드 출처에 같은 파일을 사용한다. [소형 검사](../../../../models/bcap/r/test_prepare_raw.R)는 복사한 실행 사본의 출처/동결 해시 일치, 읽은 뒤 코드 변경 거부, 기존 출력 덮어쓰기 거부, 완료·조기완료와 연기·취소·불명·누락 상태를 검사하여 통과했다. 2026 이미 실행된 준비 사본은 수정하지 않았으며, 담당자가 실제 실행 사본·동결 사본·감사 코드의 동일 해시를 확인했다.

보강된 `prepare_raw.R` SHA-256은 `1120a5834f06723fa5477b9438f3991cab7e6f1aadecc0721772c2bcd5c983b7`, `test_prepare_raw.R`은 `af9d843ee6081fd8b5988bf6425b93754a33f1f6d9230e8afbd6e77afbf16306`이다. 위 초기 스냅샷 표는 당시 기록으로 유지한다. 2026 원본·정제본·가중치·측정 보류의 구체적인 입력 준비 상태는 [2026 보조 준비 검토](../r_history_20260928/2026_supplement_readiness.md)를 따른다.

## 구장 중복 정책 확정 후 최종 검증

위의 2020·2021 구장 충돌을 검토한 결과, 원 Python `models/bcap/data.py` 120~125행은 저장된 `schedule.dates/games` 순서로 기록을 읽고 사전의 같은 경기 키를 덮어써 **마지막 기록의 구장**을 경기 전체에 연결한다. 원 코드 SHA-256은 `6dd3b6373e94c6df3c91246f2e665ca6b74aadd0c1cddac2ce4d4b42eee37689`다. 기존 모형 정의를 유지하기 위해 R 준비기의 기본 `schedule_venue_policy`를 `legacy_last_schedule_record`로 확정했다. 명시적인 `reject` 정책도 지원하며, 구장 외 year·official_date·cutoff가 충돌하면 어떤 정책에서도 중단한다.

원본 일정에 630882는 8월 9일 Nationals Park(3309)에서 시작한 뒤 8월 14일 Camden Yards(2)에서 완료된 기록과 `Completed in Baltimore` 설명이 있다. 633224는 7월 21일 Truist Park(4705)에서 시작한 뒤 9월 24일 Petco Park(2680)에서 재개된 기록이 있다. 따라서 각각 2, 2680을 선택하는 것은 기존 Python의 경기 단위 연결을 재현하는 것이다. **이 값을 해당 경기 모든 투구의 실제 구장으로 검증한 것은 아니다.** 투구별 재개 구장 복원이나 구장 변경 민감도 분석은 수행하지 않았다.

[최종 일정 검증 코드](check_legacy_venue_policy.R)와 [감사 JSON](legacy_venue_policy_check.json)에서 2020~2026의 모든 선택 경기 구장이 원 Python의 마지막 기록 사전과 일치함을 확인했다. 두 충돌 경기의 모든 완료 기록, 원본 순번·날짜·구장명·재개 정보와 선택 여부를 보존했다. 실제 준비 감사에는 적용 정책과 config 명시 여부를 남기며, `schedule_venue_conflicts.csv`에도 충돌 기록을 저장한다. 초기 `preparation_schedule_check.json`은 엄격한 거부 정책에서 문제를 발견한 당시 기록으로 유지한다. 최종 기본 정책에서는 위 두 구장 충돌로 중단하지 않는다.

소형 검사는 기본값과 명시 정책의 동일 결과·감사 표시, 보관 순서를 뒤집었을 때 마지막 구장 선택, 명시 `reject`, year/date/cutoff 충돌 거부를 통과했다. 전체 과거 자료 적합을 다시 실행하지 않았고 완료된 준비본·결과는 수정하지 않았다.

최종 `prepare_raw.R` SHA-256: `5a9920937beae72efffeaf69914c86d66e59cf7f0014e9315322082960b231a5`. 최종 `test_prepare_raw.R` SHA-256: `37cb0b40ba9be0338f2fd962714687c229bcf5dffd0bd83a1702de65e127d7e1`. 2026-09-28 12:59:09+0900의 일정 검사 이후 현재 파일 해시가 같음을 재확인했다.
