## 8. 주 실행 5건의 독립 AIPW/OPE 검산

각 주 실행의 `artifacts/scores.pkl`에는 Y·A·p·mu0·mu1·phi0·phi1·support·policy_p1 등이 저장돼 있다. 실제 스키마와 manifest 해시를 먼저 확인한다.

기존 검산기의 PASS나 phi 평균만 재사용하지 말고, 새 검수 코드에서 다음을 복원한다. 주 실행기나 기존 검산기의 핵심 계산 함수를 호출한 결과는 독립 계산과 구분한다.

```text
phi1 = mu1 + A/p × (Y−mu1)
phi0 = mu0 + (1−A)/(1−p) × (Y−mu0)

Q1 = 같은 지지 행의 phi1 평균
Q0 = 같은 지지 행의 phi0 평균
Delta = Q1−Q0

V(d) = mean[d×mu1 + (1−d)×mu0
       + {A×d/p + (1−A)×(1−d)/(1−p)}
         × {Y−A×mu1−(1−A)×mu0}]
```

정책 확률 d는 평가 결과에서 다시 고르지 않고 해당 평가 행에 적용돼야 할 저장 정책에서 독립 복원한다.

- PITCH: A1=FB, A0=NFB, gain=관찰 Y−정책가치.
- SWING: A1=번트 포함 공격 시도, A0=Take, gain=정책가치−관찰 Y.
- 항상 0·항상 1·학습 후보·Bernoulli(.5)·실제 관찰 메커니즘·보수 정책을 같은 지지 집단에서 비교.
- fallback Bernoulli(.5)와 실제 행동 메커니즘 유지 영역을 구분.
- 보수 정책 H(Z)=0이면 기여는 Y이고 개선량 0은 정의상 결과.
- 단위는 W/선택된 현재 의사결정 행이며 PA 전체 누적 개선이 아님.

`action_values.csv`, `policy_values.csv`, `metrics.json`과 대조하고 전체·12카운트·SWING 셀의 합계, 분모, 차이, 부호를 검산한다.

허용오차를 결과 확인 전에 선언하고 최대 절대·상대 오차 및 불일치 행을 기록한다. NaN·빈 지지 집단·확률 경계·반올림을 명시적으로 처리한다.

저장 예측의 산술 일치, 원자료부터의 Y/A 연결, 적합 예측 자체의 정확성은 서로 다른 검증이다. 적합 객체가 없는 범위까지 예측 재생성을 검증했다고 주장하지 않는다. 수렴은 실제 로그·목적함수·잔차 기준을 확인하고, 합성 fixture 검사는 실제 MLB 적합 전체 검증과 구분한다.

## 9. 공통 지지·구간·등급

명세의 다음 기준과 실제 적용을 확인한다.

- propensity .05~.95
- 지원 대상 선수의 양 행동 훈련 기록 각각 30 이상
- SWING의 유효 측정·존·구종군 조건
- 최소 행 500, 행동별 ESS 200, 행동별 경기 100
- 최소 포함률 .5, 최대 경기 가중 비중 .05
- 실질 차이 .01 W
- numerical epsilon, trimming과 clipping의 구분

이 숫자는 검수 통과 기준이 아니라 검수할 구현 기준이다. 기준의 통계적 충분성도 별도로 판단한다.

행동 비율·calibration·극단 가중치·ESS·경기 집중도·known/unseen·지지 제외 사유를 복원하고, 양 행동·모든 정책의 분모가 같은지 확인한다. ESS를 독립 경기 수로 해석하지 마.

주 구간의 경기 군집 sandwich 계산, 자유도, 고정 점수 조건부 해석과 Bonferroni 가족 1,536의 실제 포함 범위를 점검한다. 출력된 모든 구간이 같은 동시 보장을 받는다고 가정하지 않는다.

trimming 민감도는 대상 집단 변화, 동일 대상 clipping은 가중치 변화로 구분한다. 최초 카운트 방문 민감도의 정렬·선택 순서, 선수 군집 민감도, 경기 간 선수·시리즈 의존성과 정책 동률 부근 불확실성을 확인한다.

RECOMMENDED/LEAN/UNCERTAIN/NO_SUPPORT, 미실행, 측정 보류, 신뢰구간 미산출을 구분한다. identification/full-learning gate가 false인 상태의 실제 등급 구현과 문서가 일치하는지 확인한다. 모든 추천이 비어 있다는 사실만으로 계산·설계를 통과시키지 않는다.

## 10. 8회 재학습 진단의 검수 범위

각 모델의 재학습 실행은 최종 개발 정책의 완전한 95% 구간이 아니라 중첩 평가 절차의 안정성 진단으로 기록돼 있다.

`refit_stability.py`와 반복별 산출물을 확인하여 다음을 독립 대조한다.

- 시즌별 경기 재추출 seed·복제 횟수.
- 같은 원 경기의 복제본이 서로 다른 fold로 갈라지지 않는지.
- outer·inner·튜닝·calibration 분할과 학습 표본 수.
- 실제 각 반복의 전처리·튜닝·nuisance·정책 재학습 범위.
- 저장된 전체/카운트 집계·부호·가중 합계·8회 평균·SD·범위·부호 빈도.

기존 비교 대상:
`columns/001-ball-count/analysis/bcap_implementation_review_20260909/verify_bootstrap.py`
및 `bootstrap_final_validation.json`.

반복별 원 행 nuisance 예측·AIPW 점수·적합 객체는 저장하지 않았다는 기록이 있다. 실제 보존 범위를 확인하고, 없으면 원 행 AIPW 재계산은 **증거 부족으로 미검증**이라고 명시한다. 저장 집계 검산을 원 점수 독립 복원이라고 표현하지 않는다.

8회 전부 같은 부호이거나 좁은 범위여도 완전한 95% 신뢰구간·인과 식별·추천 근거로 승격하지 않는다.

## 11. 외부 평가와 노출 이력

외부 실행에서는 다음을 별도로 검수한다.

- `fixed_development_predictions.pkl` 및 `fixed_prediction_diagnostics/`: 고정 개발 nuisance의 외부 예측.
- `scores.pkl` 및 주 결과표: 외부 경기 교차 적합 nuisance를 사용한 고정 개발 정책 OPE.

외부 nuisance의 알고리즘·α·calibration 절차는 개발에서 고정됐는지, 범주 사전은 외부 훈련 fold 안에서 학습했는지, 정책은 개발 최종 정책 그대로인지 확인한다. known/unseen은 최종 개발 선수 사전 기준인지 확인한다.

두 절차의 지지 집단이 다르면 성능·가치 차이를 같은 대상의 직접 비교로 해석하지 않는다.

봉인·manifest·external_access_log·코드·최종 정책 해시와 실제 파일을 대조하여 UTC 순서를 작성한다. 명령 기록은 도구 호출에서 사후 작성된 기록과 독립 shell history를 구분한다.

2023·2026은 기존 BCAI/Ridge에서 사용한 자료다. 로컬 해시 봉인은 공개 사전등록이나 모든 과거 미노출의 증명이 아니다. 봉인 전 계획, 봉인 후 기술 비교·표현 보완, 결과에 영향을 준 변경을 나눠 판정한다.

SWING 2026은 WITHHELD, 평가 0회, 대체 모델 없음이라는 기록을 확인한다. 측정 보류를 NO_SUPPORT나 외부 성과 실패로 바꾸지 마. PITCH가 현재·직전 좌표를 제외했더라도 2026 판정 환경 변화와 다른 입력·결과 메커니즘 변화의 영향까지 없어지는 것은 아니므로 노출 경로와 해석 범위를 검토한다.

## 13. 산출물과 완료 보고

새 검수 폴더에 다음을 남겨줘.

- `review.md`: 독립 검수 보고서.
- `findings.csv`: 발견 사항별 심각도·유형·근거·영향·조치.
- `validation.json`: 검사별 PASS/FAIL/NOT_VERIFIABLE/NOT_RUN, 범위·오차·분모.
- `evidence_manifest.json`: 읽고 검산한 입력·코드·출력의 경로·SHA256·환경·명령·시각.
- 독립 검산 코드와 필요한 비교표·불일치 행.
- 추가 재학습이 필요하다면 구체적인 후속 검증 계획.

발견 사항마다 다음을 기록한다.

1. 심각도: 결론 무효 / 주요 수정 / 경미 수정.
2. 유형: 확인된 오류 / 알려진 한계 / 증거 부족 / 미실행.
3. 정확한 파일·코드 줄 또는 표·행·실행 ID.
4. 재현 방법과 독립 계산 근거.
5. 영향받는 수치·등급·정책·외부 검증 주장.
6. 필요한 수정과 재검증 범위.
7. 새 버전·실행 및 외부 재노출 기록 필요 여부.

모델별로 구현·수치 재현성, 통계적 해석, 행동 권고 가능성을 나눠 평가해줘. 종합 판정은 ‘명시 범위 내 사용 가능 / 수정 후 재검수 / 증거 부족으로 판정 보류’로 제시하되 무엇에 대한 판정인지 붙인다.

“문제를 발견하지 못함”을 인과성·실시간 정책 유효성·전체 PA 개선의 인증으로 쓰지 마. 최종 답변은 주요 발견, 믿을 수 있는 결과 범위, 확인하지 못한 범위, 제작 작업에 돌려보낼 구체적인 수정 요청, 새 검수 보고서 경로 순서로 정리해줘.
