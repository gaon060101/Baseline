## 분석 목표

다음 두 질문에 답하는 모델을 만든다.

1. **투수 행동 모델**

- 실제 행동 비율
- 행동별 예상 공격가치
- 통계적으로 유리한 행동
- 행동가치 차이와 불확실성
- 현재 실제 행동과 추정 권장 행동의 차이
- 판정에 필요한 표본과 행동 겹침
- 외부 시즌에서의 재현 여부
- 통계적으로 판정할 수 없는 상황

여기서 “이상적인 행동”은 **관찰된 MLB 데이터와 충분한 행동 겹침 안에서 추정한 정책**이라는 뜻이다. 개인 역량과 선택 편향을 완전히 제거한 순수한 인과효과라고 표현하지 마.

## 기존 BCAI와의 관계

다음 모델의 역할을 명확히 구분해줘.

- `BCAI-OBS-v1.0.0`: 특정 카운트에 도달한 타석의 관찰 공격가치 `I(c)`
- `BCAI-RIDGE-v0.2.0`: 시작 선수·상황을 잔차화한 카운트 진단 `J(c)`
- `BCAP-PITCH`: 카운트별 투수 행동가치와 정책
- `BCAP-SWING`: 투구 정보를 고려한 타자 행동가치와 정책

BCAI는 현재 카운트의 상태 가치를 설명하는 기준으로 활용할 수 있다. 그러나 BCAI를 다음 상태 보상으로 그대로 넣어 같은 관찰 결과를 중복 계산하지 마.

첫 버전의 주 결과는 **행동 시점 이후 해당 PA의 최종 가중 공격가치**로 정한다. BCAI는 결과 해석과 전이 방향 검증에 사용해줘.

## 개발 및 외부 검증 자료

기본 역할은 다음과 같이 고정한다.

| 역할 | 시즌 |
|---|---|
| 개발·하이퍼파라미터 선택 | MLB 2024·2025 |
| 외부 재현 검증 | MLB 2023 |
| 외부 시간 순방향 검증 | MLB 2026-09-07까지 |

2023과 2026은 이전 Ridge 분석에서 이미 확인한 자료지만 BCAP의 행동별 결과는 아직 검토하지 않았다는 전제로 진행한다. **두 외부 시즌의 BCAP 결과를 보기 전에 모델 정의, 행동 분류, 변수, 제외 기준, overlap 기준, 하이퍼파라미터 선택법과 평가 기준을 고정하고 해시로 봉인해줘.**

외부 결과를 본 뒤 설계를 수정하면 새 모델 버전과 새 실행 ID를 사용해야 한다. 수정 후 같은 2023·2026 자료를 처음 보는 독립 검증이라고 부르지 마.

2026은 진행 중인 시즌이고 2025 공격가치 가중치를 고정 사용했다는 기존 조건을 유지한다. 2026년의 위치 측정 정의 변경도 확인한다.

KBO 수집과 분석은 이번 작업에서 시작하지 마.

## BCAP-PITCH 행동 정의

첫 버전의 주 행동은 두 가지로 제한한다.

```text
FB = FF + SI + FC
NFB = 나머지 실제 구종
```

\[
A_P\in\{FB,NFB\}
\]

자동 판정, 구종 결측, 피치아웃 등 실제 구종 선택으로 해석하기 어려운 기록의 처리 기준을 명시한다.

세부 구종 모델은 FB/NFB 모델이 안정적으로 검증된 후 보조 분석으로만 확장한다.

세부 구종 후보:

- FF
- SI
- FC
- SL/ST
- CH/FS
- CU/KC
- 기타

표본이 작거나 행동 겹침이 부족하면 합치거나 판정을 보류한다. 결과를 보고 유리하게 구종군을 다시 정의하지 마.

## BCAP-PITCH 상태 변수

투구 직전에 알 수 있는 정보만 사용한다.

기본 후보:

- 투구 전 카운트
- 주자 상태
- 아웃카운트
- 점수 차
- 이닝
- 투수·타자 좌우 조합
- 구장
- 시즌
- 선발·구원 구분이 신뢰 가능하면 역할
- 같은 PA의 투구 번호
- 이전 구종
- 이전 투구 결과
- 이전 공의 위치와 구속

현재 투구의 실제 도착 위치, 현재 투구 결과, 타자의 현재 Swing 여부처럼 **투수가 행동을 선택한 뒤 결정되는 변수는 주 propensity 및 결과 보정 변수에 넣지 마.**

투수와 타자 개인 효과는 nuisance model에 포함하되 최종 행동가치는 공통 기준 분포로 평균화한다.

## BCAP-SWING 행동 정의

주 행동은 다음과 같다.

\[
A_B\in\{Swing,Take\}
\]

Swing 후보:

- swinging strike
- foul
- foul tip
- foul bunt
- in play

Take 후보:

- ball
- called strike

HBP, 자동 판정, pitchout, 번트 시도와 체크스윙 등 애매한 기록은 별도 처리 기준을 사전에 정한다. 주 분석 포함이 어렵다면 제외하고 민감도 분석으로 확인한다.

## BCAP-SWING 상태 변수

타자가 스윙을 결정할 때 이용할 수 있었던 정보를 사용한다.

기본 후보:

- 투구 전 카운트
- 주자와 아웃
- 점수 차와 이닝
- 좌우 조합
- 이전 투구 경로
- 현재 구종 또는 구종군
- 구속
- 수평·수직 움직임
- 존 안팎
- 존 세부 구역
- 존 경계까지 거리

`launch_speed`, `launch_angle`, 타구 결과와 최종 PA 결과처럼 스윙 이후 생성되는 변수는 입력으로 사용하지 마.

`plate_x`, `plate_z`는 공이 플레이트를 통과한 실제 위치이며 타자의 의사결정 시점 정보에 대한 근사치라는 한계를 명시한다. 2026년부터 측정 기준이 바뀌었으므로 연도 간 정합성을 확보하거나 위치 기반 외부 검증을 별도 처리해줘.

타자가 구종을 실제로 완벽히 알고 스윙한다고 가정하지 마. Statcast 구종 분류와 위치는 타자의 지각 정보에 대한 사후 측정치라는 한계를 기록한다.

## 개인 역량의 처리

선수 ID를 모델에서 단순히 제거하면 개인 역량이 구종 또는 행동 효과에 섞일 수 있다.

따라서 행동 확률 모델과 결과 모델에 다음 효과를 고려해줘.

- 투수 공통 효과
- 타자 공통 효과
- 시즌 효과
- 구장 효과
- 좌우 조합
- 표본이 작은 선수 효과의 축소
- 필요한 범위의 사전 지정 상호작용

최종 행동가치는 실제 FB 투수 집단과 NFB 투수 집단을 직접 비교하지 말고, **동일한 공통 기준 상황 각각에 모든 후보 행동을 가상 적용한 뒤 평균화**한다.

미관측 선수는 개발 리그 평균 효과 0을 기본으로 처리하고, known/unseen 집단을 나눠 외부 성능을 보고한다.

“개인 역량 제거”는 관찰된 선수 효과를 보정하고 공통 분포로 표준화했다는 뜻으로 제한한다.

## 추정 방법

주 추정법은 **경기 단위 교차 적합 Doubly Robust/AIPW**를 우선 검토한다.

필요한 두 nuisance model:

1. 행동 확률 모델

\[
\pi(a|s)=P(A=a|S=s)
\]

2. 행동별 결과 모델

\[
\mu(s,a)=E[Y|S=s,A=a]
\]

행동별 평균가치 추정:

\[
\hat Q(a)=
\frac{1}{n}
\sum_i
\left[
\hat\mu(S_i,a)
+
\frac{1(A_i=a)}
{\hat\pi(a|S_i)}
\{Y_i-\hat\mu(S_i,a)\}
\right]
\]

수식을 코드와 문서에서 정확히 정의하고, 교차 적합 예측만 사용해 같은 관측치를 학습과 평가에 동시에 사용하는 문제를 줄여줘.

AIPW를 사용하기 어렵거나 더 적합한 추정법이 있다면 다음 방법을 비교하고 선택 근거를 남겨줘.

- 표준화/g-computation
- IPW
- AIPW/Doubly Robust
- TMLE
- causal forest 또는 DR learner
- 단순 결과 회귀

최종 주 추정법과 민감도 추정법을 구분한다.

## 행동 겹침과 positivity

각 상태에서 모든 행동이 실제로 충분히 관찰되는지 확인한다.

반드시 다음을 산출해줘.

- 카운트별 실제 행동 비율
- propensity 분포
- 최소·최대 propensity
- 1%, 5%, 10% 분위수
- 유효 표본 크기
- 역확률 가중치 분포
- 극단 가중치 비율
- 행동별 공통 지지 영역
- trimming 전후 결과

초기 검토 기준:

```text
propensity < 0.05 또는 > 0.95: 기본 권장 판정 제한
0.05~0.10 또는 0.90~0.95: 높은 불확실성
충분한 공통 지지: 기본 비교 가능
```

이 기준은 개발 데이터의 외부 결과를 보기 전에 확정한다. 3-0 Swing처럼 희귀 행동은 강한 결론을 피한다.

가중치 clipping이나 trimming을 사용하면 임계값별 민감도를 공개한다.

관찰되지 않은 행동 조합을 모델 외삽만으로 최적 행동이라고 추천하지 마.

## 정책 정의

각 상태에서 타자의 추정 공격가치가 가장 큰 행동을 타자 정책으로 정의한다.

\[
\pi_B^*(s)=\arg\max_a Q_B(s,a)
\]

투수는 타자 공격가치가 가장 작은 행동을 선택한다.

\[
\pi_P^*(s)=\arg\min_a Q_B(s,a)
\]

점추정 차이만으로 권장 행동을 정하지 말고 다음 등급을 사용해줘.

- `RECOMMENDED`: 행동가치 차이가 실질 기준을 넘고 불확실성 구간이 방향을 지지하며 overlap이 충분
- `LEAN`: 점추정 방향은 있으나 차이가 작거나 구간이 경계
- `UNCERTAIN`: 구간이 0을 포함하거나 외부 방향 불일치
- `NO_SUPPORT`: 행동 겹침 또는 표본 부족으로 판정 불가

실질 차이 기준은 개발 데이터에서 사전에 정하고 근거를 기록한다.

- 항상 NFB
- 카운트별 추정 BCAP 정책
- 필요한 경우 보수적 정책: 충분한 근거가 있을 때만 실제 정책 변경

### 타자

- 실제 MLB 행동 정책
- 항상 Swing
- 항상 Take
- 상태별 추정 BCAP 정책
- 보수적 정책

정책가치는 학습 자료에서 직접 재사용하지 말고 교차 적합 OPE로 평가한다. 결정론적 정책과 확률적 정책을 구분한다.

## 불확실성

같은 PA에 여러 투구가 있고 같은 경기에 여러 PA가 있으므로 경기 단위 재표본을 기본으로 검토한다.

Doubly Robust 전체 절차의 불확실성을 반영해야 한다.

- 행동 확률 모델 재적합
- 결과 모델 재적합
- 정책 선택
- 공통 기준 평균화
- 카운트별 차이

가능하면 경기 단위 bootstrap을 사용한다. 계산량 때문에 근사 구간을 사용한다면 한계와 적용 범위를 명시한다.

12개 카운트와 여러 행동을 동시에 비교하므로 개별 구간과 다중비교 조정 또는 동시 구간을 구분한다.

2024·2025 개발 데이터 안에서 경기 단위 교차 적합과 하이퍼파라미터 선택을 수행한다.

개발 과정의 모델 수렴과 예측 성능을 기록한다. BCAI-RIDGE-v0.2.0처럼 엄격한 수치 검증이 필요하면 tolerance, 반복 횟수, 목적함수와 독립 검산을 명시한다.

## 투수와 타자의 상호작용

투수와 타자의 행동은 서로 영향을 준다. 어떤 구종이 평균적으로 좋아 보여도 투수가 100% 사용하면 타자가 대비할 수 있다.

이번 첫 버전에서는 투수와 타자 모델을 각각 완성하고, 다음 조건을 만족할 때만 혼합 전략 분석을 추가한다.

- 행동별 표본 충분
- 투수 행동과 타자 대응 조합에 overlap 존재
- payoff matrix의 불확실성 계산 가능
- 외부 시즌에서 방향 재현
- 구종 선택과 Swing 결정의 시간 순서 반영 가능

가능하면 각 카운트의 투수 구종군과 타자 Swing/Take 조합에 대한 payoff matrix를 탐색적으로 만든다. 혼합전략 또는 Nash equilibrium을 계산한다면 강한 가정을 명시하고 주 결과와 분리한다.

## 모델 및 실행 관리

모델 정의 위치:

```text
models/bcap/
├─ README.md
├─ pitch/v0.1.0/
│  ├─ model_card.md
│  ├─ specification.yaml
│  └─ validation.md
└─ swing/v0.1.0/
   ├─ model_card.md
   ├─ specification.yaml
   └─ validation.md
```

칼럼별 실행은 다음 아래에 둔다.

```text
columns/001-ball-count/analysis/runs/
```

실행 ID는 `guides/analysis.md` 규칙을 따른다.

예상 예시:

```text
bcap_pitch__mlb_2024_2025__<실행일>__r01
bcap_pitch__mlb_2023__<실행일>__r01
bcap_pitch__mlb_2026_ytd_20260907__<실행일>__r01

bcap_swing__mlb_2024_2025__<실행일>__r01
bcap_swing__mlb_2023__<실행일>__r01
bcap_swing__mlb_2026_ytd_20260907__<실행일>__r01
```

각 manifest에 다음을 기록해줘.

- 모델 ID와 버전
- 실행 역할
- 입력 파일 및 SHA256
- 데이터 기간
- 표본과 제외
- 행동·상태·결과 정의
- nuisance model
- 하이퍼파라미터
- fold와 seed
- overlap 기준
- clipping/trimming
- 정책 판정 기준
- 수렴 진단
- 출력 파일과 SHA256
- 외부 검증 전에 고정된 항목
- 알려진 한계

기존 BCAI 모델과 실행을 수정하거나 덮어쓰지 마.
