# BCAP 별도 검수 인계

작성일: 2026-09-09 (Asia/Seoul). 대상: Baseline 001-ball-count.

## 1. 먼저 알아야 할 현재 상태

**이번 산출물은 첨부 프롬프트와 현재 저장된 분석 자산을 검수하기 위한 인계 문서다. BCAP 분석 완료 보고서가 아니다.** 기존 BCAI 정의·보고서·manifest·결과 CSV·수렴 기록을 확인했으며, 작성 시점에 `models/bcap/`, BCAP 실행 manifest, 학습 코드, 행동별 결과표는 없다. 첨부 프롬프트에 기술된 작업을 이미 수행했다고 해석하면 안 된다.

- BCAP-PITCH-v0.1.0 / BCAP-SWING-v0.1.0: 요청된 모델 ID. 설계 검토 단계(DRAFT에 해당), 정식 등록·구현·학습·검증 미완료.
- BCAP-JOINT: 미착수. 두 모델의 독립적인 검증 전에는 결과 모델로 만들지 않는다.
- 기존 OBS/Ridge의 수렴·외부 재현은 BCAP의 성능·인과 식별·권장 행동을 검증하지 않는다.
- BCAP 주요 수치와 12개 카운트 권장 행동은 **전부 미산출·판정 보류**다. 미실행을 `NO_SUPPORT`라는 실증 결과로 바꾸지 않는다.
- 신규 데이터 수집, 원본·기존 정제본·기존 실행 수정, KBO 분석, Drive 업로드, 외부 전송은 수행하지 않았다.

첨부 원문은 [bcap_request_original.txt](bcap_request_original.txt)에 바이트 그대로 보관한다. 원문·확인한 자산의 경로와 SHA256, 확인 범위는 [검수 증거 목록](handoff_bcap_review_evidence.json), 목록 생성·검증 코드는 [verify_bcap_handoff.py](verify_bcap_handoff.py)에 있다. 이 해시는 **문서 인계 시점의 무결성 기록**이며 외부 평가 전 모델 봉인이 아니다.

## 2. 확정 범위와 아직 고정하지 않은 사항

여기서 ‘확정’은 이번 인계의 해석·작업 범위 결정이다. 구현 명세나 학습된 모델이 확정되었다는 뜻이 아니다. 등록 시 설계의 단일 기준은 `models/bcap/<variant>/<version>/`의 카드·명세이며 본 문서는 변경 이력과 검수 연결을 담당해야 한다.

## 3. 원 프롬프트의 문제와 수정 근거

| 원문 요구 또는 모호성 | 통계·구현 문제 | 수정·보류 원칙 |
| --- | --- | --- |
| 각 투구 Y로 ‘항상 Swing/FB’ 정책 평가 | 현재 한 구의 행동가치 평균을 전체 타석의 반복 정책 가치로 읽을 수 있음 | ‘선택한 의사결정 시점 한 구에만 적용’으로 제한. 이후 상태 분포·생존·상대 반응까지 바꾸는 정책은 순차적 별도 모델 필요 |
| 교차 적합 점수로 정책 선택 및 OPE | nuisance OOF만으로 같은 점수의 정책 선택 편향은 없어지지 않음 | 정책을 고르는 자료와 그 정책을 평가하는 경기도 분리; 외부 평가용 정책은 개발에서 고정 |
| Q(a)의 AIPW 평균과 Q(s,a)의 argmax 연결 | 집단 평균 점수로 각 개인·연속 상태의 효과 및 CI를 알 수 없음 | 집단 평균 Q와 조건부 회귀 μ, 학습 정책 d를 분리. 상태별 추천에는 별도 정책 클래스와 검증 필요 |
| ‘개인 역량 제거’ 또는 선수 효과 0에서 비교 | 실제 같은 집단 표준화와 가상의 평균 선수 예측은 다름 | 각 행의 실제 선수·상황을 유지하고 양 행동 예측을 같은 행들에서 평균. 알려진 선수 효과를 일괄 0으로 치환하지 않음 |
| FB/NFB를 단일 개입처럼 해석 | 구종군 안 구종·구속·제구·선수별 사용 가능성이 달라 행동의 여러 버전 존재 | 해당 선수·상황에서 관찰된 군 내부 구종/실행 분포를 따르는 제한적 비교. 선수별 구조적 미사용은 외삽 추천 금지 |
| HBP·번트·애매한 기록을 쉽게 제외 | 실제 행동/결과에 의해 포함 여부가 달라져 선택 편향 발생. 완료 PA·IBB 제외도 미래 결과에 조건부 | 제외 뒤의 선택된 관찰집단 분석임을 명시. 행동과 무관한 사전 자격으로 정의 가능한지 검토. 불명 행동을 Take로 자동 채우지 않고 미해결 시 Swing 추천 보류 |
| 현재 구종·위치·존을 타자 상태로 사용 | 결정 후 측정한 공 특성과 실제 지각 정보가 다름; 결과별 측정 결측도 가능 | 사후 측정 기반 조건부 진단으로 한정. 실행 가능한 실시간 스윙 지침이라고 표현하지 않음 |
| 2026 위치를 단순 시즌 효과로 보정 | plate_x/z 기준면 및 sz_top/bot 정의 변화는 절편 하나로 해결 불가 | 정합성 검증 전 2026 위치 기반 Swing 외부 검증 보류. 위치 제거 모델도 다른 사전 지정 분석으로 별도 평가 |
| 외부에 개발 propensity를 그대로 적용 | 외부 실제 행동 확률이 달라지면 개발 propensity가 외부 잔차를 올바르게 재가중하지 못함 | 고정 모델 이전 성능과 외부 OPE를 분리; 외부 nuisance 교차 적합을 허용할지는 결과 열람 전에 고정 |
| trimming/clipping 전후 한 효과로 비교 | trimming은 대상 집단을 바꾸고 clipping은 편향·DR 성질에 영향 | 각각 대상·분모·임계값·포함률 명시. 효과 이동을 모형 안정성 하나로 설명하지 않음 |
| 경기 bootstrap이 전체 불확실성을 자동 반영 | 고정 OOF 점수만 재표본하면 학습·정책 선택 불확실성은 빠짐; 비매끈한 argmax와 동률도 문제 | 조건부 OPE 구간과 전체 재학습 절차 구간 구분. 동률 부근 bootstrap 타당성도 확인 |
| 외부 ‘최적 행동’ 일치율 | 외부 추정 승자는 잡음이 있는 값이며 정답이 아님 | 고정 개발 정책의 외부 가치·차이·구간 우선. 외부 승자 일치는 탐색 지표, 재학습 근거로 쓰면 버전 갱신 |

위는 이 프로젝트에 대한 방법론적 판단이다. DR 정책 평가와 정책 학습의 구분은 [Dudík·Langford·Li](https://arxiv.org/abs/1103.4601), 관찰 자료의 정책 학습은 [Athey·Wager](https://arxiv.org/abs/1702.02896), 순차 정책은 [Nie·Brunskill·Wager](https://arxiv.org/abs/1905.09751)를 참고했다. 해당 논문이 MLB 자료의 교환가능성을 입증하는 것은 아니다.

## 4. 상태·행동·결과·추정 대상의 정확한 구분

### 4.1 단위와 기준 집단

행 i=(경기 g, PA j, 투구 t), 고유키 `(game_pk, at_bat_number, pitch_number)`. 투구 전 카운트 C=(balls,strikes), balls∈{0,1,2,3}, strikes∈{0,1,2}. 반복 파울 뒤 투구도 각 의사결정 행이다. PA 최종 Y는 같은 PA의 모든 적격 행에 연결하되 독립 결과가 여러 개 생겼다고 보지 않는다.

주 분석 초안은 **카운트별 적격 의사결정 행 분포**다. 양 행동에 동일한 행·선수·상황·가중치를 사용한다. 긴 PA/반복 방문이 더 자주 포함되므로 PA당 평균과 다르다. 민감도로 최초 카운트 도달 행만 사용하는 분석을 별도 지정할 수 있다. 모든 미래 투구 수로 행 가중치를 만든 분석은 미래 경로에 조건부인 별도 추정 대상으로 취급한다.

다른 카운트의 실제 도달 집단은 서로 다르다. 0-2와 3-0 평균의 차이는 카운트를 바꾸는 인과효과가 아니다. 개발과 외부 각 시즌의 자체 공통 집단 평균도 구성 변화가 있으므로, 같은 개발 기준 분포로 운반한 결과와 구분한다. 후자는 운반 가능성·밀도비 보정 설계 없이는 산출하지 않는다.

### 4.2 상태와 측정 시점

X는 nuisance 보정 상태(선수 ID 포함), Z는 정책이 사용할 허용 상태로 구분한다.

- PITCH의 X: 현재 투구 전 카운트, 주자 3비트, 아웃, `bat_score-fld_score`, 이닝·초말, 좌우 조합, 구장, 시즌, 현재 투타 ID, PA 투구 번호, 같은 PA의 직전 구종·결과·위치·구속. 역할은 신뢰할 사전 자료가 확인될 때만 포함.
- PITCH에서 금지: 현재 구속·움직임·실제 위치·Swing·description·타구·최종 결과 및 투구 후 점수. 이전 공 정보는 PA 내 정렬 후 한 행 shift로 만들고, PA 첫 행 결측은 시작 상태로 표시한다. 투수 교체 뒤 직전 공이 다른 투수였는지도 보존한다.
- SWING의 X: 위 사전 경기 상황 + 현재 구종/구속/움직임/위치 등 공 특성의 사후 측정 대리값. 구종 분류는 완벽한 사전 인지가 아니며 위치·존이 실제 결정 시점에 정확히 알려졌다고 가정하지 않는다.
- SWING에서 금지: 현재 description을 예측 변수로 사용, launch_speed/launch_angle, 타구 유형·안타 여부, 최종 events/Y. description은 행동 라벨 구성에만 사용한다.
- PITCH 정책 Z는 첫 버전에서 카운트만 쓰는 제한 정책을 우선 검토. SWING의 Z는 카운트·공 특성 중 사전 지정된 구역/정책 클래스. 개인 ID는 보정용 X에 남기되 개인별 처방으로 자동 확장하지 않는다.
- 정규화·결측 대치·범주 사전·선수 효과·구역 경계 학습은 모두 해당 훈련 자료 안에서만 수행한다. 미래 시즌 전체 성적이나 현재 PA의 남은 투구에서 만든 요약은 금지한다.

공식 CSV 문서는 balls/strikes를 투구 전 카운트로, 구종을 Statcast 유도 분류로 설명한다. plate_x/z는 2025까지 플레이트 앞면, 2026부터 중간면이며, sz_top/bot도 ABS 존 정의로 바뀐다. 존을 단순 높이 정규화했다고 기준면 변화가 사라지지 않는다. 검증된 좌표 변환 없이 시즌을 혼합하지 않는다. [Statcast CSV 문서](https://baseballsavant.mlb.com/csv-docs), 열람 2026-09-09.

### 4.3 행동

- 투수 A=1은 FB(FF,SI,FC), A=0은 NFB. ‘그 외 문자열 전부’를 NFB로 매핑하지 않는다. 실제 구종 코드 목록을 개발 자료와 출처에서 검증하고 명세에 닫힌 목록으로 저장해야 한다. 자동 판정·구종 결측·피치아웃·의도적 볼 등의 제외와 사유별 수는 미확정·미집계다.
- 타자 A=1은 Swing, A=0은 Take. 초안 후보는 Swing=`swinging_strike`, `swinging_strike_blocked`, `foul`, `foul_tip`, `hit_into_play`; Take=`ball`, `blocked_ball`, `called_strike`. 원본에서 실제 값과 번트 인플레이 판별 가능성을 확인하기 전 확정 매핑이 아니다.
- `foul_bunt`, `missed_bunt`, HBP, pitchout, 자동 판정, 불명 description, 체크스윙 처리 정책은 미해결. foul bunt만 빼고 번트 인플레이를 남기는 비대칭 분류는 허용하지 않는다. 체크스윙이 별도 식별되지 않으면 ‘완전히 제거했다’고 쓰지 않는다.
- PITCH에서 현재 HBP는 투구 선택 뒤 발생한 결과다. HBP 결과를 근거로 현재 행을 자동 제외하지 않는다. SWING의 HBP 행동 불명 문제와 구분한다.

### 4.4 결과와 단위

Yᵢ=Wⱼ=해당 PA 마지막 기록 events에 부여한 시즌별 가중 공격가치. [OBS 명세](../../../models/bcai/observed/v1.0.0/specification.yaml)의 결과 분류를 기준으로 한다. 1B/2B/3B/HR/비고의 BB/HBP는 해당 가중치, K/OUT/OTHER는 0. OTHER는 실책 출루·아웃 없는 야수선택이며 아웃과 다르다. 희생번트 포함 여부와 행동 표본의 번트 처리는 별개다.

2024·2025와 2023 가중치는 [Ridge v0.2 명세](../../../models/bcai/ridge/v0.2.0/specification.yaml)에 저장된 기존 값이 기준이며 2026은 2025 값을 고정 사용한다. 결과 단위는 **가중 공격가치/의사결정 행**이다. PA 결과를 각 행에 붙인 평균이지, 공 하나의 즉시 득점이나 100PA당 누적 정책 개선량이 아니다. BCAI의 I/J 지수 포인트와도 다르다.

최종 기록 결측을 이전 events로 대체하지 않는다. 마지막 결과 복수·불일치, 기록 누락, 시작 0-0 미관측을 점검한다. OBS와 같은 완료 PA·IBB·타격방해 제외를 적용하면 ‘그 결과로 선택된 표본의 관찰 비교’가 된다. 무조건적인 정책 인과효과로 확장하려면 중도 종료/선택 과정을 별도로 다뤄야 한다.

### 4.5 수식과 방향

카운트 c의 공통 지지 내 평가 행 집합 T_c, Rᵢ는 그 집합 포함 지시자, n_c=ΣRᵢ. p(a|X)는 행동 확률, μ(X,a)=E[Y|X,A=a]. 평가 행이 속한 경기 없이 학습한 예측에 윗첨자 −k를 붙인다.

```text
φᵢ(a) = μ̂⁻ᵏ(Xᵢ,a) + 1(Aᵢ=a)/p̂⁻ᵏ(a|Xᵢ) × [Yᵢ−μ̂⁻ᵏ(Xᵢ,a)]
Q̂_c(a) = Σᵢ Rᵢ φᵢ(a) / n_c
Δ_P(c) = Q_c(FB) − Q_c(NFB)       # 음수이면 투수에게 FB 방향
Δ_B(c) = Q_c(Swing) − Q_c(Take)   # 양수이면 타자에게 Swing 방향
```

Q_c는 집단 평균이며 μ(X,a)는 조건부 회귀다. AIPW 점수 하나를 개인의 실제 반사실 결과나 상태별 신뢰구간으로 해석하지 않는다. 인과 해석에는 일관성(행동 버전 포함), 관측 X 조건부 교환가능성, positivity 및 적절한 표본 선택 가정이 더 필요하다. DR은 미측정 교란에 대한 이중 보호가 아니다.

## 5. 한 구 정책과 OPE

현재 한 구만 d(Z)로 선택하고 이후에는 해당 변화된 경로에 따라 관찰 환경의 행동 메커니즘이 이어진다는 제한적 질문이다. 이후의 **실제로 관측된 동일 투구열을 그대로 붙여 두는 개입**으로 정의하지 않는다. 관측 자료만으로 그 이어지는 메커니즘이 변화 후에도 같다는 것을 확인할 수는 없다.

정책 d(a|Z)는 확률 정책이며 합이 1; 결정론적 정책은 선택 행동의 확률만 1이다. 평가용 정책은 평가 경기의 Y/AIPW 점수로 선택하지 않는다.

```text
V̂_c(d) = (1/n_c) Σᵢ Rᵢ Σₐ d⁻ᵏ(a|Zᵢ) φᵢ(a)
V̂_c(observed) = (1/n_c) Σᵢ Rᵢ Yᵢ
gain_P = V(observed) − V(d)  # 양수가 투수 개선
gain_B = V(d) − V(observed)  # 양수가 타자 개선
```

‘항상 FB/NFB/Swing/Take’도 동일 T_c의 **현재 한 구** 비교다. 공통 지지 밖의 전체 리그 대상으로 extrapolate하지 않는다. 보수적 정책은 근거 있는 영역에서만 변경하고 나머지에서 실제 관찰 메커니즘을 유지하는 복합 정책으로 정의한다. 유지 영역의 평가 기여를 Y로 처리할지, 별도 고정 확률 정책으로 평가할지 명세에서 구분해야 한다.

현재 행동을 바꾸면 이후 카운트 도달 확률, PA 길이, 상대 기대가 달라진다. 이 분석의 행별 차이를 더해서 ‘모든 공에 적용했을 때의 PA 개선’으로 보고할 수 없다. JOINT payoff 표의 관찰 셀 평균만으로 순차 게임의 Nash 균형을 식별할 수도 없다.

## 6. 개인 역량 보정의 범위

양 nuisance에 투수·타자 공통 효과, 시즌·구장·좌우 조합 및 사전 지정 상호작용을 검토하고 작은 선수 표본 효과는 축소한다. 동일 X 행에 두 행동을 적용한 예측·DR 점수를 같은 가중치로 평균하여 행동별로 다른 선수 구성에서 오는 **관측·모형화된 차이**를 줄인다.

남는 한계: 당일 컨디션·부상, 투구 의도·목표 위치, 포수 사인, 심판, 타자의 지각·예상, 선수별 구종 품질과 사용 가능성, 측정 오류, 모형 오지정, 시간 변화. 선수 절편만으로 선수×행동의 품질 차이를 제거할 수 없다. 상호작용을 늘려도 행동 미사용 선수의 반사실 능력을 데이터가 알려주지는 않는다.

미관측 선수는 훈련 분포로 중심화한 해당 선수 블록 효과 0을 기본으로 하고 다른 상황 효과는 유지한다. 투수/타자 각각 known·unseen, 둘 다 known·하나 이상 unseen을 나눠 N·경기 수·오차·overlap·가치와 구간을 보고한다. ‘평균 효과 대입’은 해당 선수의 다른 행동에 근거가 생겼다는 뜻이 아니다.

## 7. 자료 분리·누수·의존성 검수

### 7.1 권고 분리 구조 — 구현 전 확정 필요

1. 2024·2025 경기를 outer 평가 fold로 분할한다. 경기 내 모든 PA·투구는 하나의 fold에만 둔다.
2. 각 outer 훈련 부분 안에서 nuisance 튜닝 및 inner 경기 교차 적합을 수행한다. 전처리·선수 사전·확률 calibration도 inner 훈련 내부다.
3. inner OOF 점수로 outer 훈련 안에서 정책·구역·판정 규칙을 선택한다. 후보 비교에도 내부 검증 자료가 필요하다. 정책 선택에 outer 평가 점수를 사용하지 않는다.
4. outer 훈련에 nuisance를 적합하고 고정된 정책을 outer 평가에 적용하여 처음 보는 점수를 계산한다. 행별 outer/inner fold와 각 예측의 학습 경기 목록 또는 해시를 저장한다.
5. outer OPE는 ‘학습 절차’의 평가다. 그 결과를 본 뒤 설계를 재선택했다면 다시 독립 평가한 결과가 아니다. 개발 전체 최종 정책의 외부 가치는 별도 보고한다.
6. 최종 개발 정책·전처리·설정·코드·환경을 고정하고 봉인한 뒤 2023/2026 BCAP 결과를 평가한다.

### 7.2 외부 nuisance의 두 역할

- 고정 개발 모델 적용: 외부 예측 성능·행동확률 calibration·지지 영역·known/unseen을 보고. 개발 propensity와 outcome 회귀가 외부에도 정확하다고 보장하지 않으므로 외부 AIPW를 자동 DR 인증으로 부르지 않는다.
- 외부 OPE 수정안: 개발 정책은 완전히 고정한 채, 미리 정한 알고리즘으로 외부 경기들을 교차 적합하여 **평가용 nuisance만** 추정. 평가 행은 자신의 nuisance 학습에 들어가지 않는다. 이는 정책 재튜닝은 아니지만 ‘모든 계수 고정 외부 모델 평가’와는 다른 절차다. 외부 최적 정책 학습은 금지하고, 허용 여부를 사전 명세에서 선택한다.

### 7.3 필수 점검과 현재 결과

| 점검 | BCAP에서 필요한 증거 | 현재 |

## 8. overlap·불확실성·판정 보류

원문의 0.05/0.95 지지 제한 및 0.10/0.90 주의 구간은 **초기 후보 기준**이다. 개발 검토 전 확정된 실증 기준으로 부르지 않는다. 최종 기준은 외부 결과 전에 고정하고 각 행동·카운트/구역에 다음을 저장해야 한다.

- 실제 행동 비율, 투구·PA·경기·선수 수, 양 행동을 사용한 선수 범위.
- p의 최소·최대, 1/5/10 및 상단 대응 분위수, calibration/Brier/log loss.
- wᵢ(a)=1(Aᵢ=a)/p̂(a|Xᵢ)의 분포와 극단 비율, ESS=(Σw)²/Σw². ESS는 독립 경기 수가 아니므로 경기별 가중 집중도도 확인.
- 공통 지지 포함률, 제외 행의 상태·선수·행동 구성, trimming 전후 **서로 다른 대상** 결과.
- clipping과 trimming 구분. 수치 오버플로 방지용 epsilon도 명세에 남기고, 지지 실패를 숨기려고 확률을 잘라 추천하지 않음.

주 AIPW와 g-computation/IPW 민감도를 동일 대상에서 비교할 계획이다. TMLE/DR learner/forest가 무조건 더 낫다고 결정하지 않는다. propensity calibration과 결과 오차가 좋아도 잔여 교란·행동 겹침을 해결한 것은 아니다.

불확실성은 평가 경기 단위로 처리한다. 전체 재학습 bootstrap은 각 복제에서 nuisance·튜닝·정책 선택·평균화를 반복해야 하며 복원추출된 같은 원 경기 복제들이 train/test로 갈라지지 않게 한다. 고정 정책/점수의 cluster 구간은 조건부 근사로만 표시한다. 12개 카운트와 Swing 다수 구역에 대한 개별 95% 구간과 동시/다중비교 조정 구간의 가족을 별도로 고정한다. 동률 부근의 비정규성과 bootstrap 한계가 해결되지 않으면 확정 추천을 제한한다.

최종 등급은 배타적 우선순위로 명세화해야 한다. 제안: (1) 표본/지지 미달 NO_SUPPORT, (2) 구간 0 포함·외부 방향 불일치 UNCERTAIN, (3) 실질 기준 δ와 조정 구간·외부 재현 모두 충족 RECOMMENDED, (4) 나머지 방향성만 LEAN. δ의 단위는 W이며 OBS ±5/15 지수 경계를 그대로 전용하지 않는다. δ·최소 ESS·경기 수·판정 구간이 아직 정해지지 않았으므로 현재 어떤 카운트에도 등급을 부여하지 않는다.

## 11. 완료·미완료와 다음 검수 순서

완료: 첨부 원문 보존, 기존 001/BCAI 자산 위치와 상태 확인, 프롬프트 문제 및 수정 방향 기록, 추정 대상/시점/단위/분리 설계의 검수 초안, 누락된 증거와 권장 보류 사유 명시, 인계 링크·증거 파일 검사.

미완료: BCAP 정식 모델 등록·기계 실행 명세·원본 투구별 감사·행동 분류 확정·SWING 선택 문제 해소·nuisance/정책 구현·개발 CV·overlap·OPE·전체 불확실성·16종 결과표·카운트 해석문·외부 봉인·2023/2026 평가. 실제 BCAP 표본/효과/CI/성능은 없음.

검수 우선순위:

1. 한 구·관찰 표본 조건부 추정 대상이 연구 질문에 맞는지, 완료 PA/행동별 제외가 허용 가능한지 판단한다.
2. Swing 행동 라벨·번트·HBP·체크스윙과 사후 공 특성의 한계를 해결하거나 모델을 진단 전용으로 제한한다.
3. 정책의 허용 상태와 nuisance 보정 상태, 공통 기준 집단, 군 내부 개입 버전을 확정한다.
4. 개발 자료 안에서 실행 가능한 분리·overlap·추론 설계를 정하고 모델 카드/명세/검증 문서·레지스트리에 등록한다.
5. BCAP 구현·독립 검산 후 외부 전 봉인을 만든다. 기존 데이터가 있다는 이유로 외부 행동별 결과를 먼저 확인하지 않는다.
6. 각 단계 결과와 이력을 새 실행에 저장하고 이 인계의 완료 상태·링크를 갱신한다. 근거가 끝내 부족하면 추천 없이 판정 보류를 최종 결과로 인정한다.
