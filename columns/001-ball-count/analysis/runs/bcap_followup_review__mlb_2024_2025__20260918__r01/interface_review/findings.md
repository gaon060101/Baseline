# 인터페이스·출처 기계 검토 결과

검토 시점은 **2026-09-18, 루트 작업자가 검토 링크를 추가하기 전 스냅샷**이다. 이 폴더의 입력과 출력은 모두 **독립 합성 자료**이며 MLB 관측 결과나 모형 적합 결과가 아니다. 기존 파일은 수정하지 않았다.

## 결과

- 총 22개 검사를 수행해 **22 PASS, 0 FAIL**이었다.
- 독립 합성 2행에서 Take 평균 0.29, Swing 평균 0.40, 차이 0.11, 직접 회귀 차이 0.20, 분해-직접 차이 -0.09가 계산됐다. Take 기여도는 Ball 0.26·Called 0.03, Swing 기여도는 miss 0.05·in-play 0.35였다.
- HIGH와 OUTSIDE에 동시에 속하는 두 행은 전체·카운트·각 지역에서 모두 n=2였고 전체 n=4 중복은 없었다. 잘못된 평균 확률×평균 조건부 값 0.2375가 아니라 행별 합성 후 평균 0.29가 사용됐다.
- 관측 행동 진단은 Take Brier 0.08·로그손실 `-ln(0.8)`, Swing Brier 1.125·로그손실 `-ln(0.25)`와 일치했다.
- 확률합 오류, 양의 질량의 평균 누락·지원 거짓, 행동행 누락·중복, 미지 라벨, 훈련·평가 경기 중복, fold 불일치, 모순 지역, 부분 직접 비교자, 비유한 확률의 11개 고장 입력은 모두 거부됐다.
- CLI 최초 쓰기는 성공했고 같은 출력 경로 재사용은 거부됐으며 파일 SHA256은 변하지 않았다.
- description 12개 행동 매핑은 `BCAP-SWING-v0.2.0` 명세와 일치했다.
- 완료된 세 실행의 매니페스트가 선언한 소형 입력·코드·설정·출력 33개 SHA256은 모두 현재 파일과 일치했다.
- 후속 보고서 Markdown의 수치 토큰 611개가 HTML에 모두 존재했다. HTML에만 있는 추가 `001` 한 개는 문서 제목의 칼럼 번호였다. CSV 산술은 재계산하지 않았다.
- 새 모델 카드·검증 문서·보고서·handoff에서 파싱한 로컬 링크 165개는 모두 존재했다.
- `document_update.json`의 기록 이후 README, column.md, handoff 문서 3개는 후속 추가로 해시가 바뀌었고 registry, sources, followup 문서 3개는 그대로였다. 이를 변경 가능한 문서 이력으로 분류했으며, 불변 코드·실행 결과의 해시 불일치로 세지 않았다.

초기 실행 중 나타난 21/22 표시는 제품 실패가 아니라 검증기 파싱 문제였다. HTML 제목의 `001`을 본문 수치 불일치로 잘못 세던 규칙을 문서 구조에 맞게 고쳤고, 최종 `checks.json`은 22/22 PASS로 일관된다.

## 증거

- `checks.json`: 기대값·실제값·원본 해시·증거 유형
- `synthetic_input.json`, `synthetic_output.json`: 독립 합성 입력과 직접 호출 결과
- `cli_output.json`: 새 파일 전용 CLI 결과
- `verifier.py`: 표준 라이브러리 검증기

이 PASS는 합성 인터페이스와 기계적 출처 일관성에만 적용된다. 구성요소 모형의 통계 설계, MLB 적합, 경험적 검증 또는 모델 상태 승격을 뜻하지 않는다.
