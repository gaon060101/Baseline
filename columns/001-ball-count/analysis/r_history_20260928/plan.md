# R 과거 연도 확장 계획 — 2026-09-28

사용자가 2024·2025 재현 후 과거 연도로 계속 계산하고 BCAP도 함께 만들도록 지시했다. 순서는 2023→2022→…→2015이며 각 연도는 별도 실행으로 보존한다. 2026은 기존 선택에 따른 보조 범위지만 위치·스윙 측정 보류는 유지한다.

- BCAI: 기존 OBS 정의를 유지하고 시즌별 가중치·0-0 기준을 적용한다. 연도 내 경기 bootstrap 2,000회. 각 연도의 동시 구간은 그 연도 11카운트에 대한 것이며 여러 연도 전체의 검정으로 확대하지 않는다.
- BCAP: 현재 PITCH-v0.2.0, PITCH-SB-v0.1.0, SWING-v0.2.0의 R 구현을 우선 만들고, 구종 보조인 FF-v0.1.0도 같은 계산부를 사용한다. 개발 자료는 기존 분할·선택 규제값과 대조한다. 과거 연도 적용은 연도 안의 3fold 보조 모형 적합이며 미래 예측·인과 검증이 아니다.
- 과거 자료는 처음 보는 무오염 시험 집합으로 주장하지 않는다. 2023은 이미 분석된 자료다. 여러 해를 보고 유리한 연도만 고르지 않는다.
- 데이터는 연도별 완료 정규시즌 일정과 비교한다. 미확보·누락·중복·미분류·측정 차이를 기록하고 통과하지 못한 연도는 완료로 표시하지 않는다. 2020은 단축 시즌이다.
- 2015·2016 구속은 공식 설명상 PitchFX에서 보정한 값, 2017 이후는 Statcast다. BCAP-SWING의 물리량 비교에서는 이를 한계로 기록한다.
- 새 자료는 공식 Statcast CSV에 한정한다. 원본·과거 결과는 보존한다. 접근 거부·차단을 우회하지 않는다. 원본 재배포·외부 게시·Drive 업로드는 하지 않는다.
- 제공 조건 확인: 2026-09-28 CSV 설명 및 MLB 이용약관 확인. 자동 수집 제한 조항이 있으며 별도 허가·재배포 권한은 미확인인 기존 기록을 유지한다. 사용자 요청의 로컬 분석 범위에서 취득 시도를 기록한다.
- 시즌 가중치: 2024·2025는 기존 manifest, 2023은 기존 검증 명세. 2015~2022는 FanGraphs 공식 Guts 표의 검색 색인에서 확인된 값이다. 당일 페이지 직접 열기는 403으로 실패해 본문 재확인과 구분하며 출처·확인 상태를 남긴다.
- 결과를 목표로 규칙·규제값·지지 기준을 수정하지 않는다. 실패와 자료 부족도 전체 진행표에 남긴다.

## BCAP 과거 연도 계산 전 고정한 실행 기준

- 네 모듈의 2024·2025 R 재현 검사(보조 추정값·AIPW·지원 마스크·집계)가 모두 통과한 뒤 과거 연도 적합을 시작한다.
- `tools/run_bcap_history.py`는 완료된 BCAI 실행의 원자료 출처와 해시를 연결하고, R 원자료 준비→네 모듈 순차 계산→저장 집계표 보고 순서로 처리한다. Python은 실행·파일 확인만 담당한다.
- 각 과거 연도에서 네 모듈 합계 232개 보고 집합에 대해 사전에 고정한 보수적 상한 255를 Bonferroni 보정에 사용한다. 연도별 가족이며 여러 연도 전체 95% 보장은 아니다. 개발 재현의 기존 가족219/255와 구간 폭이 다를 수 있다.
- 연도별 R 경기 분할은 `20260928 + year` 난수 시드로 기록한다. 기존 Python 분할과 같다고 주장하지 않는다. 규제값과 지원 기준은 고정하며 연도별 결과를 보고 재튜닝하지 않는다.
- 완료 실행·준비 결과가 있으면 확인 후 재사용한다. 불완전 결과는 덮어쓰지 않고 중단해 새 ID 필요성을 알린다. 일정 경기 목록 일치는 투구 한 행까지 완전함을 보증하지 않는다.

### 중단 경기의 구장 연결 — 2020·2021 BCAP 적합 전 확인

보존된 일정에서 2020 경기630882와2021 경기633224는 중단 후 다른 구장에서 재개해 동일 경기ID의 구장 값이 다르다. 기존 `models/bcap/data.py`의 구장 연결은 보관된 일정 순서의 마지막 레코드를 사용하는 경기 단위 사전이다. R 준비도 `legacy_last_schedule_record` 정책으로 그 정의를 유지하고, 같은 경기의 구장만 다른 모든 기록·선택 기록·정책을 감사에 남긴다. 연도·공식일·기준일 충돌은 계속 거부한다. 어떤 구장이 더 유리한 결과를 만드는지 보고 선택하거나 해당 경기를 삭제하지 않는다.

이 정책은 투구마다 실제 던진 구장을 복원하는 것이 아니다. 중단 경기 전체에 마지막 완료 일정의 구장을 연결하는 기존 방식의 한계를 보존한다. 새 설정에는 정책을 명시하며, 이미 동작 중인 순차 실행기가 만든 설정에 항목이 없으면 BCAP 준비의 동일 기본값을 쓰고 감사 JSON에 기본값 사용 사실을 기록한다. 명시적 `reject` 정책도 지원한다. 2022~2025의 완료된 입력에는 이 구장 충돌이 없어 기존 준비·적합을 바꾸지 않는다.
